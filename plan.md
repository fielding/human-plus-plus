## Goal
- Create a Neovim (0.9+) Lua plugin that replicates all 4 features of the VS Code extension: (1) color theme, (2) human intent marker highlighting, (3) inline diagnostic badges, (4) markdown H1 highlighting
- Integrate the colorscheme generator into `tools/build.py` so `palette.toml` remains the single source of truth
- Follow existing project conventions (generated outputs, `make build`, `scripts/apply.sh`)

## Non-goals
- Classic Vim support (deferred — Neovim-only for now)
- Treesitter-based syntax highlighting queries (the colorscheme links standard Vim groups; Treesitter captures inherit automatically via Neovim's built-in linkage)
- Publishing to a Vim plugin registry (can come later)
- Semantic token highlighting (VS Code extension explicitly disables it)

---

## Constraints (write as `!!`)

!! Marker detection MUST only occur inside comments — the 10 comment-pattern regexes (or Treesitter comment nodes) are the gatekeeper. Bare `!!` in code must NOT be highlighted.
!! Explicit markers (`!!`, `??`, `>>`) always override keyword aliases on the same line.
!! Keyword matching must be case-insensitive with word boundaries — `TODOBUG` must NOT match.
!! Only ONE diagnostic badge per line — highest severity wins (error > warning > info > hint).
!! Diagnostic messages truncated to 50 chars (47 + `...` if over).
!! Hints disabled by default (the only setting that defaults to false).
!! Marker decoration covers from comment symbol start to trimmed line end — NOT whole-line.
!! Markdown H1 is whole-line highlighting (different from markers).
!! base0F (lime) is RESERVED for `!!` markers — must not appear in general syntax groups.
!! The Neovim colorscheme MUST be generated by `tools/build.py` from `palette.toml` — no static color files.
!! Plugin must require Neovim 0.9+ and `termguicolors` for correct rendering.

## Approach

### Architecture
The plugin lives at `packages/neovim-plugin/` (parallel to `packages/vscode-extension/`). It follows standard Neovim Lua plugin layout: `lua/human-plus-plus/` for the runtime, `colors/` for the colorscheme, `plugin/` for auto-load.

The colorscheme file (`colors/humanplusplus.lua`) is **generated** by a new `generate_neovim()` function in `tools/build.py`, just like `generate_vscode_theme()` generates the VS Code theme from a template. All 24 palette colors flow from `palette.toml` through the generator into `vim.api.nvim_set_hl()` calls.

The runtime features (markers, diagnostics, H1) are written by hand in Lua — they are logic, not colors, so they don't need to be generated. They reference highlight groups defined by the colorscheme.

### Comment detection strategy
Primary: Treesitter comment node queries via `vim.treesitter.get_node()` — performant (incremental parsing), accurate, supports all languages with TS parsers. Fallback: regex patterns (direct port of the 10 from extension.ts) for buffers without a Treesitter parser active.

### Event mapping
- `BufEnter`/`BufWinEnter` → full update (replaces `onDidChangeActiveTextEditor`)
- `TextChanged`/`TextChangedI` → debounced marker update (replaces `onDidChangeTextDocument`)
- `DiagnosticChanged` autocmd → debounced diagnostic update (replaces `onDidChangeDiagnostics`)
- `vim.defer_fn()` for debouncing (replaces `setTimeout`)

## Alternatives considered

- **Option A: Template-based colorscheme (mustache like VS Code)**
  Would create a `.lua.tmpl` file with `{{base00}}` placeholders. Matches the VS Code pattern exactly but adds template file management overhead for a relatively simple output.

- **Option B: f-string generation in build.py (chosen)**
  The generator function directly produces Lua source code using Python f-strings, like `generate_ghostty()`, `generate_bat()`, and most other generators do. Simpler, no template file to maintain, and the Lua output is straightforward enough that a template is unnecessary.

- **Option C: Ship a static Lua colorscheme + runtime palette loader**
  Would ship a Lua file that reads palette.toml at runtime. Rejected: adds runtime dependency on palette.toml being present, doesn't match the "generate everything from palette.toml" project convention, and wouldn't work when the plugin is installed standalone.

Option B is best: it's what most generators in build.py already do, keeps the pipeline simple, and the Lua output is deterministic.

```lua
  '^(%s*)(/[%*]+)',       -- /* block
  '^(%s*)(%*)',           -- * block continuation
  '^(%s*)(<!%-%-)',       -- HTML/XML
  '^(%s*)(%%)',           -- LaTeX
  '^(%s*)([Rr][Ee][Mm]%s)', -- Basic/Batch
}

--- Check if line is a comment using Treesitter (returns start_col or nil)
local function ts_is_comment(bufnr, line_num)
  local ok, parser = pcall(vim.treesitter.get_parser, bufnr)
  if not ok or not parser then return nil end

  local tree = parser:parse()[1]
  if not tree then return nil end

  local root = tree:root()
  -- Check if any node at this line is a comment
  local node = root:named_descendant_for_range(line_num, 0, line_num, 0)
  while node do
    if node:type():match('comment') then
      local sr, sc = node:start()
      if sr == line_num then return sc end
    end
    node = node:parent()
  end
  return nil
end

--- Regex fallback for comment detection
local function regex_comment_start(line_text)
  for _, pat in ipairs(COMMENT_PATTERNS) do
    local ws, prefix = line_text:match(pat)
    if ws then
      return #ws  -- start col of comment symbol
    end
  end
  return nil
end

--- Scan a single line for marker content (after comment is detected)
local function scan_marker_content(comment_text, enabled_markers)
  -- First: check explicit markers (!!, ??, >>)
  for _, mtype in ipairs({ 'intervention', 'uncertainty', 'directive' }) do
    local def = MARKERS[mtype]
    if enabled_markers[mtype] then
      local escaped = def.pattern:gsub('%?', '%%?'):gsub('>', '%%>')
      if comment_text:match('^%s*' .. escaped .. '(%s|$)') or
         comment_text:match('^%s*' .. escaped .. '$') then
        return mtype
      end
    end
  end

  -- Second: keyword aliases with priority
  local best_type, best_priority = nil, math.huge
  for _, mtype in ipairs({ 'intervention', 'uncertainty', 'directive' }) do
    if enabled_markers[mtype] then
      for _, kw in ipairs(KEYWORDS[mtype] or {}) do
        -- Case-insensitive word boundary match
        local lower_text = comment_text:lower()
        local lower_kw = kw:lower()
        -- Check for word boundary using %f frontier pattern
        if lower_text:match('%f[%w]' .. lower_kw .. '%f[%W]') then
          if MARKERS[mtype].priority < best_priority then
            best_type = mtype
            best_priority = MARKERS[mtype].priority
          end
          break
        end
      end
    end
  end
  return best_type
end

--- Scan buffer and return list of {type, line, start_col, end_col}
function M.scan(bufnr)
  local cfg = config.options
  local lines = vim.api.nvim_buf_get_lines(bufnr, 0, -1, false)
  local matches = {}

  local enabled = {}
  for mtype, _ in pairs(MARKERS) do
    enabled[mtype] = cfg.markers[MARKERS[mtype].config_key].enable
  end

  for i, line_text in ipairs(lines) do
    local line_num = i - 1  -- 0-indexed
    -- Try Treesitter first, then regex
    local comment_start = ts_is_comment(bufnr, line_num)
    if comment_start == nil then
      comment_start = regex_comment_start(line_text)
    end

    if comment_start then
      local comment_text = line_text:sub(comment_start + 1)
      -- Strip the comment prefix to get content
      -- (find where actual content starts after //, #, etc.)
      local _, prefix_end = comment_text:match('^(%s*)(///)')
                         or comment_text:match('^(%s*)(//)')
                         or comment_text:match('^(%s*)(#)')
                         -- ... (same patterns, extract content after prefix)
      local content = comment_text  -- simplified; actual impl strips prefix

      local mtype = scan_marker_content(content, enabled)
      if mtype then
        local trimmed_end = #(line_text:match('^(.-)%s*$'))
        table.insert(matches, {
          type = mtype,
          line = line_num,
          start_col = comment_start,
          end_col = trimmed_end,
        })
      end
    end
  end
  return matches
end

--- Apply marker extmarks to buffer
function M.update(bufnr)
  vim.api.nvim_buf_clear_namespace(bufnr, ns, 0, -1)

  if not config.options.enable then return end

  local matches = M.scan(bufnr)
  for _, match in ipairs(matches) do
    local hl = MARKERS[match.type].hl
    vim.api.nvim_buf_set_extmark(bufnr, ns, match.line, match.start_col, {
      end_col = match.end_col,
      hl_group = hl,
      priority = 200,  -- above syntax, below diagnostics
    })
  end
end

return M
```

Risks:
- Treesitter `get_parser()` can throw if no parser installed — wrapped in `pcall`.
- Lua pattern matching doesn't have `\b` word boundary — using `%f` frontier pattern instead.
- Performance: full-buffer scan on every keystroke (debounced). For very large files, could limit to visible range via `vim.fn.line('w0')`/`vim.fn.line('w$')`.
- Mitigation: debounce (step 5) ensures scan runs at most every 200ms.

### Step 4: Create diagnostic badge module (`lua/human-plus-plus/diagnostics.lua`)

What:
- Render inline diagnostic messages as virtual text after the affected line
- One badge per line, highest severity wins
- Messages truncated to 50 chars
- Uses `vim.diagnostic.get()` to fetch current diagnostics

Where:
- `packages/neovim-plugin/lua/human-plus-plus/diagnostics.lua` (new)

How (snippet):
```lua
local config = require('human-plus-plus.config')

local M = {}

local ns = vim.api.nvim_create_namespace('hpp_diagnostics')

local SEVERITY_ORDER = {
  [vim.diagnostic.severity.ERROR] = { level = 'error', hl = 'HppDiagError', rank = 1 },
  [vim.diagnostic.severity.WARN]  = { level = 'warning', hl = 'HppDiagWarn', rank = 2 },
  [vim.diagnostic.severity.INFO]  = { level = 'info', hl = 'HppDiagInfo', rank = 3 },
  [vim.diagnostic.severity.HINT]  = { level = 'hint', hl = 'HppDiagHint', rank = 4 },
}

function M.update(bufnr)
  vim.api.nvim_buf_clear_namespace(bufnr, ns, 0, -1)

  local cfg = config.options
  if not cfg.enable or not cfg.diagnostics.enable then return end

  local diagnostics = vim.diagnostic.get(bufnr)

  -- Group by line, keep highest severity per line
  local by_line = {}
  for _, diag in ipairs(diagnostics) do
    local line = diag.lnum
    local info = SEVERITY_ORDER[diag.severity]
    if not info then goto continue end

    -- Check if this level is enabled
    if not cfg.diagnostics[info.level].enable then goto continue end

    if not by_line[line] or info.rank < by_line[line].rank then
      by_line[line] = {
        rank = info.rank,
        hl = info.hl,
        message = diag.message,
      }
    end
    ::continue::
  end

  -- Render virtual text
  for line, entry in pairs(by_line) do
    local msg = entry.message
    if #msg > 50 then
      msg = msg:sub(1, 47) .. '...'
    end

    vim.api.nvim_buf_set_extmark(bufnr, ns, line, 0, {
      virt_text = { { '  ' .. msg .. '  ', entry.hl } },
      virt_text_pos = 'eol',
      priority = 150,
    })
  end
end

return M
```

Risks:
- `vim.diagnostic.get()` returns all diagnostics; iterating is O(n) — fine for typical files.
- `DiagnosticChanged` autocmd fires frequently — debounce in step 5 mitigates.

- Only one badge per line, highest severity
- Disabling `diagnostics.hint.enable` (default) means hint badges don't show

### Step 5: Create markdown H1 module (`lua/human-plus-plus/headings.lua`)

What:
- Detect ATX H1 (`# Heading`) and setext H1 (line followed by `===`) in markdown buffers
- Apply whole-line lime background highlighting using extmarks with `hl_eol = true`

Where:
- `packages/neovim-plugin/lua/human-plus-plus/headings.lua` (new)

How (snippet):
```lua
local config = require('human-plus-plus.config')

local M = {}

local ns = vim.api.nvim_create_namespace('hpp_headings')

function M.update(bufnr)
  vim.api.nvim_buf_clear_namespace(bufnr, ns, 0, -1)

  local cfg = config.options
  if not cfg.enable or not cfg.markdown.h1_highlight.enable then return end

  -- Only markdown buffers
  if vim.bo[bufnr].filetype ~= 'markdown' then return end

  local lines = vim.api.nvim_buf_get_lines(bufnr, 0, -1, false)

  for i, line in ipairs(lines) do
    local line_num = i - 1

    -- ATX H1: ^# followed by space and content
    if line:match('^#%s+.+$') then
      vim.api.nvim_buf_set_extmark(bufnr, ns, line_num, 0, {
        end_row = line_num,
        end_col = #line,
        hl_group = 'HppMarkdownH1',
        hl_eol = true,
        priority = 100,
      })
    end
  end

  -- Setext H1: non-empty line followed by ===
  for i = 1, #lines - 1 do
    local next_line = lines[i + 1]
    if next_line:match('^=+%s*$') then
      local current_line = lines[i]
      if current_line:match('%S') then  -- non-empty
        -- Highlight both lines
        for _, ln in ipairs({ i - 1, i }) do  -- 0-indexed
          vim.api.nvim_buf_set_extmark(bufnr, ns, ln, 0, {
            end_row = ln,
            end_col = #lines[ln + 1],
            hl_group = 'HppMarkdownH1',
            hl_eol = true,
            priority = 100,
          })
        end
      end
    end
  end
end

return M
```

Risks:
- ATX pattern `^#%s+.+$` won't match `#` alone (requires content) — this matches VS Code behavior.
- Setext detection: must index carefully (Lua 1-indexed vs extmark 0-indexed).

Verification:
- Open a markdown file with `# Heading One` and setext headings
- H1 lines should have full-width lime background
- H2+ headings should NOT have lime background

### Step 6: Create main init module (`lua/human-plus-plus/init.lua`)

What:
- Provide the `setup()` entry point that users call from their config
- Register autocommands for buffer events (BufEnter, TextChanged, DiagnosticChanged)
- Implement debouncing via `vim.defer_fn()`
- Register `:HumanPPToggle` and `:HumanPPRefresh` user commands

Where:
- `packages/neovim-plugin/lua/human-plus-plus/init.lua` (new)

How (snippet):
```lua
local config = require('human-plus-plus.config')
local markers = require('human-plus-plus.markers')
local diagnostics = require('human-plus-plus.diagnostics')
local headings = require('human-plus-plus.headings')

local M = {}

local marker_timer = nil
local diag_timer = nil
local augroup = nil

local function update_all(bufnr)
  markers.update(bufnr)
  diagnostics.update(bufnr)
  headings.update(bufnr)
end

local function schedule_markers(bufnr)
  if marker_timer then
    marker_timer:stop()
  end
  marker_timer = vim.defer_fn(function()
    if vim.api.nvim_buf_is_valid(bufnr) then
      markers.update(bufnr)
    end
  end, config.options.debounce_ms)
end

local function schedule_diagnostics(bufnr)
  if diag_timer then
    diag_timer:stop()
  end
  diag_timer = vim.defer_fn(function()
    if vim.api.nvim_buf_is_valid(bufnr) then
      diagnostics.update(bufnr)
    end
  end, config.options.debounce_ms)
end

function M.setup(opts)
  -- Check Neovim version
  if vim.fn.has('nvim-0.9') ~= 1 then
    vim.notify('human-plus-plus requires Neovim 0.9+', vim.log.levels.ERROR)
    return
  end

  config.setup(opts)

  -- Clean up previous autocommands if re-calling setup
  if augroup then
    vim.api.nvim_del_augroup_by_id(augroup)
  end
  augroup = vim.api.nvim_create_augroup('HumanPlusPlus', { clear = true })

  -- BufEnter / BufWinEnter → full update
  vim.api.nvim_create_autocmd({ 'BufEnter', 'BufWinEnter' }, {
    group = augroup,
    callback = function(ev) update_all(ev.buf) end,
  })

  -- TextChanged / TextChangedI → debounced marker update
  vim.api.nvim_create_autocmd({ 'TextChanged', 'TextChangedI' }, {
    group = augroup,
    callback = function(ev) schedule_markers(ev.buf) end,
  })

  -- DiagnosticChanged → debounced diagnostic update
  vim.api.nvim_create_autocmd('DiagnosticChanged', {
    group = augroup,
    callback = function(ev) schedule_diagnostics(ev.buf) end,
  })

  -- User commands
  vim.api.nvim_create_user_command('HumanPPToggle', function()
    config.options.enable = not config.options.enable
    local bufnr = vim.api.nvim_get_current_buf()
    if config.options.enable then
      update_all(bufnr)
      vim.notify('Human++ highlighting enabled')
    else
      markers.clear(bufnr)
      diagnostics.clear(bufnr)
      headings.clear(bufnr)
      vim.notify('Human++ highlighting disabled')
    end
  end, {})

  vim.api.nvim_create_user_command('HumanPPRefresh', function()
    if config.options.enable then
      update_all(vim.api.nvim_get_current_buf())
    end
  end, {})

  -- Initial update for current buffer
  local bufnr = vim.api.nvim_get_current_buf()
  if vim.api.nvim_buf_is_loaded(bufnr) then
    update_all(bufnr)
  end
end

return M
```

Risks:
- `vim.defer_fn` returns a timer object that needs `.stop()` — verify this works correctly in Neovim 0.9 (it may return differently). Alternative: use `vim.uv.new_timer()` directly.
- Mitigation: test debounce behavior manually; switch to `vim.uv` timer if needed.

Verification:
- Command: Add `require('human-plus-plus').setup({})` to init.lua, open a file
- Markers, diagnostics, and H1 highlights should appear
- `:HumanPPToggle` should disable/enable all highlighting
- `:HumanPPRefresh` should force a re-scan
